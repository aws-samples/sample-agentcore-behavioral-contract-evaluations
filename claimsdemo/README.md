# claimsdemo — the demo claims agent

AgentCore CLI project for the [behavioral contract evaluations sample](../README.md). It deploys a small pharmacy-claims agent to AgentCore Runtime with observability enabled — in **two implementations** (Strands and LangGraph, both Claude Sonnet 5 on Bedrock), validated by the **same** behavioral contract.

Follow the [quickstart in the root README](../README.md#quickstart); this file only covers what is specific to this directory.

## The agent's two modes

Both implementations accept the same payload; a `mode` field selects the behavior (`scripts/invoke_agent.py` sets it):

| Mode | Behavior | Contract verdict |
|---|---|---|
| `compliant` | Follows the process: `check_coverage` → `lookup_formulary` → `render_decision`, cites the policy | PASS 8/8 |
| `lazy` | Answers from parametric knowledge — no tools, fabricated citation | FAIL 4/8, named violations |

Member `MEM-003` has expired coverage: in compliant mode the agent legitimately skips the formulary lookup (fast deny) and still passes, because those constraints are gated on the `check_coverage` result. See [the contract](../evaluator/contracts/claims.yaml).

## Layout

```
claimsdemo/
├── agentcore/
│   ├── agentcore.json            # Project config: runtimes, evaluators, online-eval configs
│   ├── aws-targets.json.example  # Copy to aws-targets.json, set your account + region
│   └── cdk/                      # CDK app the CLI deploys (@aws/agentcore-cdk)
├── app/claims_agent/             # Strands implementation: main.py, tools.py, prompts.py
├── app/langgraph_claims_agent/   # LangGraph implementation: same tools, prompts, and modes
└── AGENTS.md                     # CLI-generated schema reference for AI coding assistants
```

The two implementations share tool names, tool data, and prompts by design — that's what lets the single contract in [`evaluator/contracts/claims.yaml`](../evaluator/contracts/claims.yaml) validate both (its `applies_to: ["*claims_agent*"]` matches both runtime service names).

## Commands you'll use here

```bash
agentcore deploy --yes    # deploy/update the CDK stack (AgentCore-claimsdemo-default)
agentcore status          # deployment status, runtime ARN
agentcore run eval ...    # on-demand evaluation (quickstart step 5)
agentcore logs            # runtime logs
```

## Note on local state

Quickstart step 3 (`agentcore add evaluator`) and step 6 (`agentcore add online-eval`) write your Lambda ARN — including your account ID — into `agentcore.json`. That's expected for your own deployment; don't commit it if you fork or redistribute this sample. `aws-targets.json` is gitignored for the same reason.
